# 把 QuickRead 改成适合自己的版本

从阅读关注点、详略和样式开始。下面的指令可直接交给项目里的 Agent；替换其中的任务和偏好即可。

## 更关注技术研究，或更关注产品商业

```text
我想用 QuickRead 阅读技术访谈。请检查现有 Profile、Lens 和提示词，
让新案例优先围绕机制、证据、关键实验和适用边界组织内容。
优先使用现有 knowledge 类型和 research 视角；根据材料保留合适的类型。
保留发言者归属、限定条件和来源依据。调整后说明影响范围。
```

商业方向可以改为：

```text
我更关心产品与创业决策。请用现有 strategy 类型及 product、startup 视角，
突出目标、约束、选择理由、结果和代价。材料中没有的信息保持缺省。
请先应用于下一个新案例，并沿用项目的核验与审查流程。
```

实际入口是 [profiles 配置](../config/profiles.json)、[类型提示词](../prompts/profiles/) 和分阶段 [prompts](../prompts/)。现有类型包括知识、战略、叙事、辩论和综合；视角包括研究、产品、创业等。

选择已有类型和视角适合作为第一步。若新增类型，还需要同步工作流中的固定枚举和校验规则，由 Agent 一起检查。

## 调整详略

```text
我希望新案例的速读更紧凑，优先保留关键结论、推理链和重要边界。
请检查 config/pipeline.json 的 budgets.brief 与编辑提示词，
提出并实施一致的阅读预算调整；阅读时间继续根据实际字数估算。
不要为了凑字数删掉关键限定，保留深度稿和证据册入口。
```

实际入口是 [阅读预算配置](../config/pipeline.json)、[综合提示词](../prompts/03-synthesize.md) 和 [速读编辑提示词](../prompts/04-edit.md)。当前速读预算以 3,000–8,000 字为范围，并根据材料密度调整；长度指标用于规划。

这些偏好需要 Agent 协调配置、提示词及相关检查。对已有案例改写正文时，继续执行对应内容审查与渲染流程；修改偏好后，新案例才会按新约定生成。

## 改变阅读样式

```text
请把 QuickRead 的阅读页面调整成暖白底、低饱和蓝色强调的样式，
正文保持手机上清楚可读。先修改 templates/quickread.css，
保留层级和来源定位，检查桌面与手机溢出，再重新渲染指定案例。
只调整视觉呈现，保留该案例的正文和证据引用。
```

实际生效的入口是 [quickread.css](../templates/quickread.css)。顶部 CSS 变量控制画布、正文和强调色；字号、间距和响应式规则也在此文件中。截图尺寸和移动端导出参数位于 [pipeline 配置](../config/pipeline.json) 的 `render` 字段。

请让 Agent 检查实际渲染结果。`config/design-tokens.json` 当前主要供设计检查使用，修改它不会自动改变渲染器读取的 CSS。

## 一次修改，明确影响范围

在指令里说明“仅下一个案例”“指定案例”或“全局样式”。全局提示词和 CSS 会影响后续处理或重新渲染的案例，已生成文件需要经过对应构建命令才能更新。

新偏好可以保存在自己的项目约定中；已有案例正文、证据与审核记录仍按 [AGENTS.md](../AGENTS.md) 管理。更多内部命令见 [技术流程](workflow.md)。
