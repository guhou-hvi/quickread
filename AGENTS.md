# QuickRead Longform Agent Protocol

This repository is operated through conversation. When the user asks to process a local subtitle or article, carry the task through to validated Markdown, HTML, and both PNG formats unless the source path is missing or unreadable.

## Trigger contract

Typical requests: `处理 inbox` or `处理 <path>，来源链接为 <optional URL>`.

1. For `处理 inbox`, scan only supported top-level files in `inbox/`. If exactly one exists, choose a short `<person>-<topic>` ASCII descriptor and run `npm run ingest -- <descriptor>`. Intake assigns the next `QR-NNNN` number. If several files exist and the user did not name one, list them and ask which file to process; do not batch them implicitly.
2. If the path is outside both `inbox/` and `cases/`, use `npm run init-case -- <descriptor> <path>`; this copies the source and never deletes the external original.
3. Read the allocated directory printed by intake, then run `npm run parse -- cases/qr-NNNN-<descriptor>` and continue the full workflow without another checkpoint.
4. Read `case.json`, then run the workflow prompts from `00` through `05` in numeric order. Do not collapse profile selection, extraction, research, synthesis, editing, blind recall, semantic coverage, fidelity, and reader review into one pass or one Agent context.
5. Keep source material immutable. Derived files belong in `work/` or `output/`.
6. Generate all deliverables before requesting the normal single review checkpoint.
7. Complete `shortTitle`, `participants`, `tags`, publisher, date, and source-link status before delivery. Never leave corrupted placeholder text such as `???`.
8. If no source URL was supplied, search for the original page. Adopt it only when at least two of title, participant, publisher, and duration agree. Otherwise keep `source.url` null, mark it `pending`, and record candidates and reasons in `work/source-match.json`.

## Non-negotiable provenance rules

- `source_fact`: directly stated or shown in the supplied source; attach evidence IDs.
- `speaker_view`: a speaker's interpretation, prediction, preference, or recollection; attach evidence IDs and never present it as established fact.
- `external`: information found outside the supplied source; attach citation IDs and label it as background or fact-checking.
- `editorial`: synthesis produced by the agent; in quick-read output render it only as the dedicated `QR-Pilot` editor note and never attribute it to a speaker. The deep-read reader edition contains no QR-Pilot/editor-note blocks.
- Quotes must match normalized source text. If ASR wording is doubtful, paraphrase and record the uncertainty instead of polishing it into a quote.
- Advertisement exclusion is deliberately high precision: only explicit sponsor reads or promotional calls to action may be auto-excluded. Substantive discussion containing words such as “广告” or “赞助” remains mapped, and the quality gate rejects a generic-keyword exclusion.

## Required workflow

### Public distribution defaults

This distribution starts with no cases and no migration authorization. Never inherit historical repair overrides or batch approvals from another repository. New material follows the complete workflow below. Retained-case migration requires the owner's explicit case-level authorization before adding IDs to configuration. No existing numbered case is implicitly authorized by its number.

Evidence change gate: run `npm run evidence-check -- cases/<slug>` after evidence work, then run `npm run evidence-diff -- cases/<slug>` against the last accepted baseline. A `mechanical` change needs deterministic checks only. A traceable `semantic_delta` uses `review-prepare --claims-delta` and reviews only changed claims, their source neighbourhood, affected themes, and affected reader blocks. A `structural_full` change requires one full Claim Auditor. Missing or unreliable lineage, changed source/normalised-source hashes, rebuilt segment ownership or speaker mapping, and a case with no accepted baseline are structural-full conditions. Participant and key-term background never change evidence and never enter Claim Auditor.

1. `npm run parse -- cases/<slug>` to normalize the source and create an unmapped coverage ledger.
2. Apply `prompts/00-profile.md`, write the source-hash-bound `work/profile-assessment.json`, then run `npm run profile -- cases/<slug> --assessment work/profile-assessment.json`. If the top score is below 0.75 or leads by less than 0.15, ask once for confirmation before extraction.
3. Run `npm run segment -- cases/<slug>` and apply `prompts/01-extract.md`; write `segments.jsonl`, coverage 2.0, and atomic claims in `evidence.jsonl` 2.0. Atomic means one proposition that can be judged as a whole, not one verb per record: tightly linked predicates that share a speaker, source, qualifier and semantic purpose may stay together. Split only independently testable facts or views whose support, attribution, importance or truth value can diverge; never split merely to improve a count.
4. Apply `prompts/02-research.md`; verify risky names, numbers, ASR wording, and external context before synthesis. Also create `work/participant-guide.json` when the material is an interview, debate, roundtable, or multi-guest conversation. Identities are factual external context as of the event date; omit unverifiable fields and never put policy positions, ideological judgments, rankings, or election predictions in the guide. When a non-person product, project, organization, technology, concept, or event recurs and is necessary for a broad reader to follow the argument, create `work/context-guide.json`. Select by narrative function and comprehension need, not occurrence count; each entry separates its source-backed definition, cited external background, and source-backed relevance. Do not create a glossary wall or put people in this guide.
5. For a new case with no accepted baseline, run the full isolated Claim Auditor and claim-gate process once. After an accepted review, save a baseline with `npm run evidence-diff -- cases/<slug> --accept`. For later changes, follow `evidence-change-set.json`: `mechanical` runs only deterministic evidence checks; `semantic_delta` runs `npm run review-prepare -- cases/<slug> --claims-delta --assign claim_auditor=<reviewer-id>` and then `npm run review-validate-delta -- cases/<slug>`; `structural_full` runs one full Claim Auditor. Claim Gate is activated for a delta only when the delta auditor reports a concrete semantic hard error or an unresolved semantic disagreement. Mechanical changes, proactive wording edits, and participant-guide work do not consume a repair attempt.
   If the first full Claim Audit itself returns a concrete repair before an accepted baseline exists, do not repeat the full audit. For a new case without a migration archive, first run `node scripts/initial-audit-input.mjs cases/<slug>` while the reviewed evidence is still unchanged. It freezes the hash-bound full-audit input, verifies normalized text by re-parsing the immutable source, and checks the packet's cited source units; it is not a content approval. After the independent Repair Editor applies the adjudicated changes, run `npm run evidence-diff -- cases/<slug> --seed-initial-audit-repair`. This command may create a temporary pre-repair baseline only when the migration archive or verified new-case input snapshot, full-audit hashes, repair log, unchanged source/segments, and exact changed refs all agree. Then run only the generated claims-delta review and accept the final baseline after that delta passes. Any missing or mismatched lineage still escalates to `structural_full`.
6. Apply `prompts/03-synthesize.md`; write `theme-map.json`, a selective `claim-bundles.json`, `output/deep-read.json`, and `reader-map.json` 2.1. New 2.4.2 artifacts use deep-read schema 2.5.0 with an adaptive participant guide. Key-term background never has a standalone `context_guide` block: mark exactly the first substantive paragraph, list item, comparison column or quick-read section lead with `contextRefs`, and let the renderer place the three-line “是什么／背景／本期作用” note immediately after it. Titles, transitions and editorial blocks do not count as substantive first use. A section lead counts when it already explains the term's role rather than merely announcing a later discussion. If an otherwise substantive node merely previews a particular term, list only that term in `contextPreviewRefs`; do not reclassify the whole node or move several cards into the overview. Header summaries remain navigation surfaces and do not carry notes. Context entries never enter reader-map or source coverage. Bundles plan only claims actually used in reader prose; they need not cover every claim or map one-to-one to reader blocks. Bundle size, unbundled claims, paragraph count and body coverage are diagnostics and never authorize adding text. Compose the deep-read in third-person, restrained observer prose; 12,000–18,000 Chinese characters and 6–8 chapters are targets rather than gates. Timeline/navigation is optional and deep-read contains zero QR-Pilot blocks. Run `npm run build-deep -- cases/<slug>` to render `deep-read.md` and `evidence-book.md`. Atomic claim text must not be dumped into reader prose.
7. After the Claim Auditor baseline and reader edition are ready, prepare the smaller reader-first review with `npm run review-lite-prepare -- cases/<slug> --round <N> --assign source_scout=<id> --assign fidelity=<id> --assign reader_advocate=<id>`. Prepare the separate participant check with `npm run participant-review-prepare -- cases/<slug> --assign external_citation=<id> --assign reader_advocate=<id>`. Each packet is isolated and self-contained; reviewers must read only their assigned packet. Source Scout reports only omissions that could change the core understanding, Fidelity checks published statements for concrete support and provenance, and Reader Advocate reports concrete comprehension problems. Numeric scores, length and coverage remain diagnostics.
8. Run `npm run review-lite-validate -- cases/<slug> --round <N>` and `npm run review-lite-consensus -- cases/<slug> --round <N>`, then record the two-role participant result with `npm run record-participant-review -- cases/<slug>`. For a new or changed key-term guide, prepare three isolated packets with `npm run context-review -- prepare cases/<slug> external_citation=<id> fidelity=<id> reader_advocate=<id>`, validate them, then record the inherited baseline with `npm run context-review -- record cases/<slug> baseline=<reader-consensus-path>`. Context-only work checks citations, the exact definition/relevance split, first-use timing and term-wall risk; it does not start Claim Auditor, Source Scout, Blind Recall or Coverage, and does not consume a repair attempt. Only concrete unsupported, contradicted, misattributed or fabricated statements; wrong provenance; invalid citations; stale/hash/schema/reference/render-integrity failures; and a core omission independently confirmed by two roles are hard errors. A core omission must be a complete, recoverable source proposition whose absence changes a core conclusion, mechanism, decision logic, key boundary or important counterexample. Ordinary partial/missing observations, disagreement and all quantitative diagnostics do not block. The latest completed `round-NN` is used for finalization; an incomplete newer round never conceals the last valid consensus.
   For a local reader repair, create the next round with `--base-round <N>` and one `--change <reader-block-id>:<text|evidence_refs|citation_refs|provenance>[,...]` per changed leaf. Text changes rerun only Fidelity and Reader Advocate; evidence/citation/provenance-only changes rerun only Fidelity. The new consensus inherits untouched roles from the immutable base round. Do not rerun Source Scout unless a block was added, removed, moved, retyped, or the edit may alter the core understanding; those structural cases are rejected by the targeted command and require a normal three-role round. Any undeclared reader-leaf change or source/evidence/research change invalidates the delta.
   If the only change is merging duplicate `reader-map` entries for one evidenceRef into one entry with the identical union of coverage spans, use `--reader-map-mechanical`. It creates no Agent packets, consumes no repair attempt, and inherits all three reports only after proving that evidenceRef, importance, presentation, readerBlockRef and readerTextQuote are unchanged and every non-readerMap input hash is identical. To seal an older complete report set after the working reader has already changed, `review-lite-validate` and `review-lite-consensus` accept explicit `--historical`; this disables only the current-worktree binding and still validates the old manifest, packet, report and consensus lineage. Never use historical mode for finalization of current content.
9. If consensus returns a concrete hard-error repair queue, assign it to a separate Repair Editor. A readability warning is repaired only when the user explicitly selects it. Apply only the named qualifier, number, causality, counterexample, provenance, contradiction, attribution or confirmed core-omission repair; never add prose to improve a percentage, count, score or target length. Record `repair-log.json`, invalidate the brief when reader content changes, and use the change set to rerun only affected roles. Evidence changes no longer imply a fresh full review: changed claims need delta Claim Auditor review; changed source-backed reader blocks need Fidelity; changed reader prose needs Reader Advocate; Source Scout runs only when an addition/deletion may change the core understanding. Blind Recall and Coverage A/B are not automatically rerun. Stop after two repair attempts and ask the user if a concrete hard error remains.
   A semantic evidence repair must update `evidence-migration.json` (when present), `theme-map.json`, and `claim-bundles.json` for the affected scope. The default cap is two repair attempts. Any attempt above two is legal only when the user explicitly authorizes that named case and `config/pipeline.json` records the exact case-number cap. Mechanical changes, participant-guide changes, proactive reader rewrites, and warnings do not increment `repairAttempt`.
   `reviewRound` is the formal audit label; `repairAttempt`/`repairLog.repairRound` is the case-level count of authorized semantic repair attempts. They are independent counters. For a high-numbered formal round, pass the actual attempt with `npm run review-consensus -- cases/<slug> --round <review-round> --repair-attempt <attempt>`; never infer the repair count from the review label.
10. Only after the deep read passes multi-Agent review, apply `prompts/04-edit.md`. New 2.4.2 outputs use brief 1.7.0 and bind the selected key-term subset with `placement: inline_first_use`; this binding never renders a standalone guide. Then run `npm run quality -- cases/<slug>`, `npm run validate -- cases/<slug>`, `npm run render -- cases/<slug>`, and `npm run screenshot -- cases/<slug>`.
11. Inspect both full PNGs at original detail. If the phone image exceeds 24,000 px, also inspect every generated `quickread-mobile-NN.png` share segment. Present `quickread-mobile.png` as the default phone artifact.
12. Run `npm run catalog` and ensure both case catalogs are current. Multi-Agent approval does not replace the normal concentrated human checkpoint. Agents must never create, fill, or alter `work/human-review.json` on the user's behalf.

New artifacts use top-level workflow `2.4.2`, prompt `3.4.2`, and review policy `2.4.2`. Existing artifacts keep their recorded workflow, prompt, deep-read, reader-map, quality, and retained-review versions; a default-version change alone never makes a retained case stale or unfreezes it. Context Upgrade is disabled by default in this public distribution; explicit owner approval and a configured allowlist are required for retained-case upgrades.

Before synthesis creates `theme-map.json`, run the evidence change gate with `--extraction-only`; after synthesis, run the complete `evidence-check` without that flag. This preflight never substitutes for the final theme-map check.

## Content defaults

- Audience: broad knowledge readers without assumed domain context.
- Output: Simplified Chinese; preserve original proper nouns.
- Quick-read: 4–8 thematic sections and `3,000 + 250 × density.total` Chinese characters, bounded to 3,000–8,000, with source anchors.
- Reader edition: third-person, restrained observer prose for broad readers. Aim for 12,000–18,000 Chinese characters and roughly 6–8 coherent chapters, but neither value is a pass threshold, minimum, maximum or permission to pad. Only a concrete fidelity repair or a core omission confirmed by two independent roles justifies adding text.
- Emotional fidelity: keep the calm observer voice without flattening the guest's authentic anxiety, frustration, courage, doubt, metaphors or criticism. Strong judgments remain explicitly attributed. Controlled `spoken_cleanup` quotes may delete only disfluency, repetition, false starts and clear ASR noise; they preserve order, meaning and original code-switching.
- Evidence archive: every claim actually cited by the reader edition or brief remains traceable to support. Evidence-book/source-to-claim coverage is diagnostic; low-value details need not be atomized or repeated merely to reach a percentage.
- Deep-read contains no QR-Pilot blocks. Timeline/navigation is optional; lists, paragraphs and chapter counts follow the material rather than quotas.
- External context is encouraged when useful, but it must never be blended into source claims.
- For articles, use heading/paragraph locators instead of fabricated timestamps.

## Definition of done

- The source ledger exposes mapped, excluded and unexplained units. Mapping, exclusion and recall ratios are diagnostics; a ratio alone never blocks delivery or authorizes expansion.
- Every retained evidence claim and every source-derived statement actually published in the reader edition or brief has contiguous, semantically matching support. Coverage percentages do not substitute for this statement-level check.
- Blind Recall, Alignment, evidence-book coverage, author-declared reference coverage, body coverage and near-duplicate ratios remain visible diagnostics. Only a concrete contradiction or a core omission confirmed by two independent roles blocks on content completeness.
- Speaker confidence is diagnostic. Use a name only when attribution is supported; otherwise retain `unknown` or a verified `speakerMap`. A concrete wrong attribution is a hard error.
- All brief evidence/citation references resolve.
- No unlabelled external or editorial claims remain.
- Deep-read has no editorial blocks. Every quick-read editorial block uses `editor_note` with a controlled `intent`, a viewpoint title, and one body paragraph; its identity, Chinese action label, and style come from the renderer.
- `summary` means a faithful compression of the guest's position and must include evidence references. Use `commentary` for interpretation, `critique` only for a supported challenge or hidden trade-off, and `caution` for risks or boundary conditions.
- HTML passes desktop and mobile overflow checks.
- Desktop PNG is 1660 px wide, mobile PNG is 1080 px wide with at least 15 px effective body text on a 390 px display, and both are visually inspected.
- Reader prose contains no claim index, coverage statistics, subtitle dump, ASR residue, visible provenance labels or speaker-turn fragments. Repetition, list share, list length, paragraph length, chapter count and navigation density are diagnostics; Reader Advocate reports a concrete comprehension blocker instead of failing a number.
- `deep-read.md` and `evidence-book.md` exactly match deterministic rendering from their machine sources. Every actual `reader-map.json` entry quotes a matching eligible source block; unexpressed claims need no placeholder mapping. Timeline, system, external and QR-Pilot blocks never count toward body-coverage diagnostics.
- Review roles use recorded reviewer IDs and isolated packets. Reports bind to local claim, support-span, citation, and reader-block hashes: only changed dependencies become stale. `review-validate-delta` must reject an undeclared affected claim or reader block. Historical reports remain immutable.
- Participant-guide facts are external, cited, and anchored to the event date. New guides use schema 1.1.0: `eventDate` accepts a valid `YYYY-MM` or `YYYY-MM-DD`, while `verifiedAt` remains a valid full date. Preserve verified precision in Markdown and HTML; never invent a day. Existing 1.0.0 guides retain full-date compatibility, and `dateBasis` distinguishes event from publication dates. The detailed deep-read guide and compact quick-read guide share `work/participant-guide.json`; neither contributes to subtitle coverage or reader-map evidence expression.
- Key-term definitions, external background and interview relevance share `work/context-guide.json`. Deep-read and quick-read use that single source, render all three fields immediately after the first substantive occurrence, never render a standalone key-term guide in 2.4.2, never place people in the guide, and contribute zero to subtitle coverage, recall, reader-map expression or repair-attempt counts.
- Claim-gate secondary review is restricted to the primary semantic nonpass set; matching decisions resolve directly, disagreements require independent adjudication, and validated quote-only mechanical repairs never consume a semantic repair round.
- Derived artifacts and review reports contain no U+FFFD replacement characters or repeated-question-mark encoding placeholders.
- Human review records completeness, fidelity, traceability, hierarchy, Profile fit and readability for the user's concentrated checkpoint. Numeric scores inform that decision but do not replace it or impose an automatic 4/5 gate.
- The case number, directory, manifest ID, profile, evidence, research, reader map, deep read, evidence book, brief, HTML, quality report, and render report agree; the searchable catalogs are current.
