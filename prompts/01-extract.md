# 01 — 语义片段与原子 claim 抽取（Prompt 3.2）

## 目标

先建立来源覆盖，再建立观点覆盖。只抽取可核验的语义单位，不写发布文案，不根据预期篇幅制造 claim。机械按字符数切片、按关键词或序号赋重要度均被禁止。

## 输入边界

允许输入：`case.json`、已确认的 profile、`work/source.normalized.jsonl`、`work/segments.jsonl`，以及人工 `speakerMap`。

禁止输入：旧版或当前 `deep-read`、`brief`、`reader-map`、质量分数、字符目标、其他审核者结论。下游稿件不能反向决定来源中“应该”有什么。

## 两层模型

1. 检查 `segments.jsonl`：每个 segment 必须拥有一段连续、唯一的 `sourceIds`；`contextBefore/contextAfter` 只供理解，不算所有权。不能在一个论证、故事转折或问答中间机械切断。
2. 更新 `coverage.json` 2.0：每个来源单元只能映射一个 segment，或以寒暄、广告、噪声、完全重复等具体原因排除。不得映射到 evidence。自动排除广告只适用于明确的赞助口播或推广行动；讨论广告商业模式、项目资助或合作赞助的实质句必须保留。
3. 写 `evidence.jsonl` 2.0：一行只表达一个可核验 claim。claim 可为事实、观点、预测、回忆、例子、反驳、限制或不确定性。
4. 每条 claim 写 `importance`、`claimRole`、`themeId`、说话人状态和一个或多个连续 `supportSpans`。跨段重复观点只保留一条 canonical claim，但保存全部出现位置。

## 原子性规则

在综合稿尚未生成时，执行 `npm run evidence-check -- cases/<slug> --extraction-only` 检查来源、支持区间与提取结构。综合完成后再执行不带此参数的完整检查，核对 theme-map 归属。

- 一条 claim 只允许一个主要谓词、一个说话人和一种认识状态。事实与推测、主张与反驳、原因与结果不能因相邻而强行合并。
- 主持人的问题和嘉宾的回答必须分开；问题本身通常不是 claim，除非它明确陈述了需要核验的前提。
- 同一来源区段包含多个独立数字、条件、例子或结论时必须拆分；同一观点跨多个区段重复时必须合并。
- `supportSpans` 必须完整支持 statement 中写明的指代对象、阶段名称、关系标签、情态强度和因果方向。若当前区间只有“它”“这一阶段”“两者”等指代，应增加包含 antecedent 的连续区间或另一个连续 span；找不到支持时删去该扩写，不得靠常识补全。
- 保留原文的认识强度：“可不可以”“可能”“设想”不得升级成计划或确定结论，“一种主流”不得扩写成唯一主流，“有助于”不得扩写成必要条件。
- 字符长度只用于发现异常，不得作为切分依据。不得保留 ASR 口癖、残句、轮次粘连或多个说话人混杂的 statement。
- `claimRole` 由整段语义决定，不以“但是”“未来”“我觉得”等单个词匹配。

## 重要度规则

- `high`：删除后会改变访谈的核心结论、关键决策、主要机制、重要因果链或成立边界。
- `medium`：解释 high claim 的机制、关键证据、代表性例子、反例、限制或转折。
- `low`：寒暄之外仍可检索，但不影响读者理解主线的枝节、重复例子或背景细节。

重要度不得由 ID 奇偶、出现顺序、数字存在与否、字符长度或主题热词自动决定。若无法解释“删除它会损失什么”，不得标为 high。

## 归属与原文

- `source_fact` 只表示来源直接陈述或展示的内容；`speaker_view` 用于解释、预测、偏好、回忆和判断。
- 只有明确标签或高置信上下文才归属具体说话人。置信度低于 0.85 时 `name` 必须为 `null`、`status` 为 `unknown`。
- 引语必须匹配规范化来源。ASR 专名或数字可疑时记录疑点，不得擅自润色成确定引语。
- `themeId` 按语义归属，不按时间等分；跨主题 claim 选择承担其论证功能的主主题，相关主题通过图谱关系连接。
- ID 稳定、有序：segment 使用 `S0001`，claim 使用 `E0001`。

完成时 `coverage` 不得有 `unmapped`，每个 claim 都必须有可连续回查的 `supportSpans`。抽取者不得审核自己的结果；下一步必须交给 `reviews/claim-auditor.md` 与 `reviews/blind-recall.md` 独立检查。
